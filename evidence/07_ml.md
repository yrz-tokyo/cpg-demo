# ML — 衝突レビューの行列を並べ替える

## このモデルが何をするのか（1文）

**検出器が出した82グループのレビュー行列を並べ替えて、スチュワードが上から見るだけで
本物の定義衝突に当たるようにする。** 新しい知見を発見する装置ではなく、**処理量を上げる装置**。

## なぜ ML が必要なのか

検出器（`10_detect/detect_conflicts.py`）は metric view の同名 measure を見る。
`12_ml/extract_features.py` はそれを silver 30本とマート13本の数値列すべてに広げた。

```
数値列 309 列 → 同名グループ 82 件 / 関与する列 201 列
```

**82件を毎回人が全部見るのは現実的でない。** しかも大半は衝突ではない
（同じ列が core → mart に集計されただけ）。並べ替えが要る。

## 学習データ

| | 件数 |
|---|---|
| 特徴量（`semantics_ops.conflict_feature`） | **82 グループ** |
| ラベル=1（本物の衝突） | **27** |
| ラベル=0（衝突ではない） | **55** |
| 衝突率（母比率） | **33%** |

### ラベルの出所を正直に書く

**ラベルは構築者がスチュワード役として付けたものです。** 実在の業務担当者の合議ではありません。
データが合成なので実在のスチュワードは存在しません。方針は
[`12_ml/LABELING_POLICY.md`](../12_ml/LABELING_POLICY.md) に先に書き、
**1グループずつ列コメントと実測値を読んで**付けました。
41件は「同じ列が core→mart に集計されただけ」という方針の一括適用で、
その旨を `rationale` 列に明記しています。

したがってこのモデルについて言えるのは **「保留したスチュワード判断を再現できる」** までで、
**「人の知らない衝突を見つけた」ではありません。**

## 特徴量（15個・メタデータとデータだけから取る）

| 特徴量 | 何を捉えるか |
|---|---|
| `n_objects` / `n_schemas` | 同名の列を持つオブジェクト数・スキーマ数 |
| `n_departments` | 関与する部門数（スキーマの subdomain タグから） |
| `log_max_over_min` | その列で集計した値の最大/最小比の対数 |
| `cross_layer` | core と mart の両方に跨るか → **跨る場合は同じ列の集計である可能性が高い** |
| `n_currencies` / `currency_mixed` | 関与する表の建値が混ざるか |
| `in_metric_view` | metric view の measure として露出しているか（業務が実際に触る面） |
| `certified_count` | 認定済みオブジェクトの数 |
| `comment_jaccard_avg` | 列コメントの語の重なり → **低いほど別概念** |
| `comment_missing` | コメントが欠けていたか（欠損自体が偶然一致の目印になりうる） |
| `name_has_amount` / `_rate` / `_count` / `_usd` | 列名のトークン |

## 必ずベースラインと比べる

モデルを置く前に、**モデルを使わない並べ方**がどれだけ強いかを測った。

| 並べ方 | PR-AUC | ROC-AUC | 上位16件の適合率 |
|---|---|---|---|
| ランダム | 0.498 | 0.659 | 56% |
| `n_objects` 降順 | 0.605 | 0.704 | 75% |
| `max_over_min` 降順 | 0.675 | 0.892 | 69% |
| ロジスティック回帰（交差検証） | 0.806 | 0.862 | 88% |
| **勾配ブースティング（交差検証）** | **0.955** | **0.979** | **100%** |

**ベースラインは既に強かったが、モデルはそれを明確に超えた。**
上位16件（全体の2割）が**全部本物の衝突**で、母比率は33%。
つまり**82件を全部見る代わりに上位16件を見れば足りる**。

選ばれたのは勾配ブースティング。UC に
`rongzi_catalog_dev.semantics_ops.conflict_ranker` **version 1** として登録済み。

### 上位10件（交差検証のスコア順・label は実際の判断）

```
gross_amount            0.998  label=1  2部門  18.3倍
total_gross_amount      0.998  label=1  3部門  15.3倍
tax_amount              0.997  label=1  3部門  17.3倍
total_net_amount        0.997  label=1  3部門  14.8倍
total_tax_amount        0.996  label=1  2部門   3.0倍
net_amount              0.996  label=1  2部門  17.9倍
trade_discount_amount   0.996  label=1  2部門   5.5倍
total_amount            0.996  label=1  2部門   1.6倍
dollar_sales            0.996  label=1  2部門   4.0倍
total_actual_spend_usd  0.993  label=1  1部門  18.3倍
```

`total_amount`（1.6倍）と `total_tax_amount`（3.0倍）が上位に来ているのが
ベースラインとの差。**値の差が小さくても部門が違えば衝突**という判断を再現している。
逆に `max_over_min` 順では上位に入ってしまう `cpc`（14,862倍）や
`equity_score`（79.5倍）を、`cross_layer` と `comment_jaccard` で落とせている。

`max_over_min` 順の上位20件に混ざる label=0 の7件は、
`cpc` / `cpm` / `avg_roi_index` / `equity_score` / `awareness_pct` /
`acv_distribution_pct` / `tdp` — いずれも**生列の合計とマートの集計を比べたために
比が極端になっただけ**で、概念は1つ。
モデルがベースラインに勝つとすれば、`cross_layer` と `comment_jaccard` でここを落とせるかどうか。

## 評価の仕方

- **層化5分割交差検証**（ラベルが 27:55 で偏るため）
- 見るのは **PR-AUC** と **上位20件の適合率**。不均衡データでは正答率は意味が薄い
- 2モデル（ロジスティック回帰 / 勾配ブースティング）を比べ、PR-AUC で選ぶ
- すべて MLflow に記録（experiment `2943466170842971` / run `deb159adf992`）、
  UC に `rongzi_catalog_dev.semantics_ops.conflict_ranker` version 1 として登録
- 並べ替えた結果そのもの（`conflict_ranking.csv`）を artifact に残し、
  **上位が本物かを目で見られる**ようにする

## ループが閉じるところ

```
検出（82グループ）→ モデルが並べ替え → App でスチュワードが上から裁く
        ↑                                              ↓
        └── 却下ペアは再提案しない ←── Lakebase に永続化 ──→ ラベルが増える
```

`semantics.ml_training_label` ビューが `decision` から機械的にラベルを導出するので、
**App のクリックがそのまま次回の並べ替えの学習データになる。**
いま Lakebase 側の判断は2件で、これは cold start。
82件のラベルは UC 側（`semantics_ops.conflict_label`）に置いてある。

## 再現手順

```bash
python3 12_ml/extract_features.py        # 82グループの特徴量を作る
python3 12_ml/label.py --review          # 未ラベルを人が読む形で出す
python3 12_ml/label.py --apply           # 特徴量とラベルを UC に書く
./12_ml/run_training_job.sh              # serverless で学習 → MLflow → UC 登録
```

serving endpoint は**デモ直前に立てて後で消す**（立てている間課金されるため）。
